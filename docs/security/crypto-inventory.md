# Meet Aaron — Cryptographic inventory and key lifecycle

Version 1.1 — 23 October 2026 — complete inventory of the production code base
(searched: createCipheriv, createDecipheriv, createHmac, createHash, randomBytes,
randomInt, randomUUID, getRandomValues, timingSafeEqual, subtle, Math.random,
bcrypt/jose/jsonwebtoken, pgcrypto). Re-checked at every release that touches
lib/encryption.ts or adds a dependency.

**No custom cryptography.** Meet Aaron implements no cipher, hash, MAC, random
generator, key derivation or signature scheme of its own. Every operation below
is a call to Node.js `crypto` (OpenSSL 3), the browser Web Crypto API, PostgreSQL
`gen_random_uuid()` / `gen_random_bytes()`, or a vetted platform (Supabase Auth,
Stripe SDK, Vercel TLS).

## A. Operations performed by our code

| # | Purpose | Primitive | Parameters | Where |
|---|---|---|---|---|
| 1 | OAuth tokens + IMAP/SMTP passwords at rest | AES-256-GCM | 256-bit key, fresh 96-bit IV per value, 128-bit tag verified before any plaintext | lib/encryption.ts |
| 2 | Signed click-tracking links (no open redirect) | HMAC-SHA-256 | sub-key derived from TOKEN_ENCRYPTION_KEY by HMAC; 128-bit truncated tag, constant-time compare | lib/marketing-tracking.ts |
| 3 | Youtrust webhook authenticity | HMAC-SHA-256 | constant-time compare (timingSafeEqual) | app/api/webhooks/youtrust |
| 4 | Stripe webhook authenticity | HMAC-SHA-256 (Stripe SDK constructEvent) | 5-min tolerance | app/api/webhooks/stripe |
| 5 | Password-reset and e-mail-verification tokens | CSPRNG crypto.randomBytes(32) | 256 bits, single use, time-limited (reset: 1 h) | app/api/auth/* |
| 6 | OAuth `state` nonces (Google, Microsoft, CRMs) | crypto.randomBytes(16) | 128 bits, bound to an HttpOnly Secure cookie (10 min, path-scoped), single use | app/api/auth/<provider> |
| 7 | Quote tracking tokens | crypto.randomBytes(16) | 128 bits | lib/devis-tracking.ts |
| 8 | Calendar (ICS) feed token | crypto.randomUUID | 122 bits | app/api/agenda/ics-link |
| 9 | Team seat / legacy invite codes | crypto.randomBytes(4) / (3) | 32 / 24 bits + rate limit 5 tries per 15 min per account, 20 per IP | lib/invite-code.ts, app/api/join-company |
| 10 | Video room names | crypto.randomInt (CSPRNG, unbiased) | 32 chars from 36 symbols ≈ 165 bits; rooms expire 3 h after the meeting | lib/video-room.ts (Math.random replaced 23 Oct 2026) |
| 11 | Browser device identifier (new-device alert) | Web Crypto randomUUID / getRandomValues | 122-128 bits (no Math.random fallback since 23 Oct 2026) | lib/supabase-browser.ts |
| 12 | Database identifiers, QR hand-off tokens | PostgreSQL gen_random_uuid() | 122 bits | SQL defaults |
| 13 | Cache key for AI suggestions (not security) | SHA-256 | non-secret input | app/api/campaigns/profile-suggestions |

Non-security uses of Math.random (never protect anything): send-time jitter
(lib/send-window.ts, lib/messaging.ts), the local part of SMTP Message-IDs
(lib/imap.ts), a temporary batch placeholder (lib/aaron-batch.ts), a Google
Calendar requestId (lib/google.ts), and confetti animation (components/WinCelebration.jsx).

## B. Operations delegated to platforms

| Purpose | Who | Algorithm |
|---|---|---|
| User password storage | Supabase Auth (GoTrue) | bcrypt; our code never sees a stored hash |
| Session tokens | Supabase Auth | JWT signed ES256 (asymmetric), 1 h lifetime; opaque single-use refresh tokens |
| MFA | Supabase Auth | TOTP (RFC 6238) |
| TLS to users | Vercel | TLS 1.3 / 1.2 only, ECDHE + AES-GCM / ChaCha20, HSTS preload — Qualys SSL Labs A+ (23 Oct 2026) |
| TLS to providers / database | Node.js fetch, Supabase | HTTPS with certificate validation (no custom trust store, no verification bypass) |
| Web Push notifications | web-push library (lib/push.ts) | VAPID JWT signed ECDSA P-256 (RFC 8292); payload encrypted aes128gcm with ECDH P-256 (RFC 8291) |
| Mail transport for IMAP/SMTP mailboxes | imapflow / nodemailer over Node TLS | TLS with certificate validation (implicit TLS or STARTTLS) |

## C. Key lifecycle

| Key | Generation | Storage | Lifetime / rotation | Destruction |
|---|---|---|---|---|
| TOKEN_ENCRYPTION_KEY | `openssl rand -hex 32` on the founder's machine, entered once | Vercel env var, type Secret (not retrievable after saving) | rotated yearly or immediately on suspicion; dual-key rotation via TOKEN_ENCRYPTION_KEY_PREVIOUS, each old-key decryption is logged until all values are rewritten | old key removed from Vercel once no value uses it |
| Derived HMAC key (tracking links) | HMAC(TOKEN_ENCRYPTION_KEY, label) at runtime | memory only | follows TOKEN_ENCRYPTION_KEY | never persisted |
| Webhook secrets (Stripe, Youtrust) | generated by the provider | Vercel Secret | rotated on endpoint change or suspicion | revoked at the provider |
| Provider API keys / OAuth client secrets | generated by the provider | Vercel Secret | yearly or on suspicion; Microsoft secrets before their Entra expiry | revoked at the provider |
| Per-user OAuth tokens | issued by Google / Microsoft / CRMs | database, AES-256-GCM | access ~1 h (refreshed); refresh revocable by the user | deleted on mailbox disconnect and on account deletion |
| One-time tokens (reset, verification, QR) | CSPRNG | database | QR hand-off 5 min, password reset 1 h, e-mail verification until its expiry; single use | consumed atomically; expired tokens refused |
| TLS certificates | Let's Encrypt via Vercel | Vercel | 90 days, automatic renewal | automatic |
